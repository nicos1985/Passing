Estados de un check

OK
El servicio cumplió las reglas configuradas: código, JSON, latencia o conectividad, según el tipo de monitor.
Respuesta lenta
El destino responde, pero supera el máximo de latencia. Se distingue de una caída y puede abrir su propio incidente tras el umbral de checks consecutivos.
Falla
El destino no cumplió una regla o no respondió. Al alcanzar el umbral de fallas consecutivas se abre un incidente.
Error del monitor
No se pudo ejecutar bien la comprobación. No confirma una caída del destino ni abre un incidente de servicio.
Sin check o detenido
No hay una medición para ese tramo o el monitor está pausado. Las barras grises indican falta de datos.

Códigos HTTP

El código indica qué respondió el servidor. Cada monitor define cuáles acepta; el valor inicial es 200-299. Incluso un código aceptado puede fallar por una regla JSON. Si supera el umbral de latencia se clasifica como respuesta lenta.

ResultadoSignificadoQué revisar
2xxSolicitud aceptada.Reglas JSON y latencia, si están configuradas.
3xxRedirección.El check no la sigue. Usá la URL final o aceptá ese código si es esperado.
401 / 403Requiere autenticación o prohíbe el acceso.Permisos del endpoint desde el servidor monitor.
404Ruta no encontrada.URL y ruta configuradas.
429Demasiadas solicitudes.Intervalo del check y límites del servicio.
5xxError informado por el servidor.Aplicación y dependencias del destino.

JSON y latencia

Si la respuesta empieza con una lista:
[{"name":"Leanne Graham"}, ...]
Ruta 0.name · Valor esperado "Leanne Graham". Los índices empiezan en cero; no agregues json. al principio.
La respuesta no es JSON válido

Llegó un cuerpo, pero no se pudo interpretar como JSON. Comprobá qué devuelve el endpoint desde el servidor monitor.

Ruta JSON no encontrada

El JSON sí es válido, pero la ruta configurada no existe. Revisá claves e índices.

Valor JSON inesperado

La ruta existe, pero el valor o su tipo es distinto. Los textos esperados se escriben entre comillas.

Respuesta JSON demasiado grande

Supera el límite de lectura de 16 KiB. Usá un endpoint de salud pequeño o quitá la regla JSON.

Latencia: para ping, HTTP, TCP y TLS podés definir un máximo en milisegundos. Si lo supera, el check aparece en ámbar como respuesta lenta. Tras la cantidad de checks consecutivos configurada se abre un incidente distinto de una caída y se avisa por los canales habilitados. Cuando hay un incidente HTTP, se puede ver una muestra JSON breve y cifrada en su detalle; se ocultan campos habituales de credenciales y contacto.

Conectividad y certificados

Ping sin respuesta

No hubo respuesta ICMP. El servidor puede estar caído o un firewall puede bloquear ping.

Puerto TCP inaccesible

No se pudo abrir una conexión al host y puerto configurados. Revisá servicio, puerto y firewall.

Certificado TLS inválido o por vencer

La cadena, el nombre o la vigencia no pasó la verificación, o faltan menos días que el umbral configurado.

Worker sin actividad

El proceso de checks no actualizó su latido en 3 minutos. Los resultados pueden estar desactualizados.
